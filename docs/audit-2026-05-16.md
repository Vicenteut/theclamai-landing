# Landing audit — 2026-05-16

**Branch base:** `main` (working dir clean per `git status`)
**Objetivo de la sesión:** alinear el landing con el lenguaje editorial del dashboard v4 (`feat/ui-overhaul-fase5-completion`).
**Alcance:** polish editorial (tipografía, status pills, paleta, light mode opcional). NO toca scope funcional del `PLAN_AUDIT_FIXES.md` existente, que sigue válido en paralelo.

---

## Resumen ejecutivo

El landing está **estructuralmente completo y consistente**: dot-grid, glow dorado en hero/CTA, paleta gold/dark, eyebrows + uppercase mono-tracking en todas las secciones, hover sutil en cards (`border-color` + `translateY(-2px)`), buena jerarquía visual, animaciones `fade-up` respetando `prefers-reduced-motion`.

Lo que falta para que “se sienta del mismo equipo” que el dashboard v4 cabe en **3 ejes** y un puñado de detalles:

1. **Tipografía editorial ausente** — el dashboard usa Fraunces (display) + JetBrains Mono (meta) + Inter (body). El landing usa Geist sans para todo. Es la gap visual más grande y la que el usuario llamó explícitamente.
2. **Status pills no comparten DSL** — el dashboard tiene `.ui-status-pill` con dot animado pulsante. El landing usa un mini-badge plano (10px uppercase) en cards verticales.
3. **Solo dark mode** — el dashboard ya tiene light theme via `[data-ui-theme]` y FAB toggle. Decisión a tomar: ¿el landing también, o queda dark-only por estrategia?

No hay **emojis** en ningún componente (grep limpio). No hay **copy fake** (testimonios/logos/métricas). Pricing está honestamente como “Contact us” en los 3 tiers — alineado con el constraint del user.

**Decisión pedida:** confirmar antes de Bloque 2 si el light mode entra (~+1h) o queda fuera de scope (recomiendo fuera — landing premium dark es una decisión de marca defendible, no un gap).

## Decisión clave: Light mode

El dashboard soporta light + dark. El landing es dark-only premium-minimal.

**Opciones:**
- **A. Mantener dark-only.** Landing es la “first impression” de marca — el premium dark/gold es defendible como decisión de posicionamiento (Linear, Vercel, Cursor lo hacen). **Recomendado.**
- **B. Agregar light theme + FAB toggle.** Coherencia total con dashboard. ~+1h. Requiere traer light tokens del dashboard, ajustar el dot-grid en light (`#0a0a0a` background del landing no aplica), portar la lógica del toggle FAB.

Si la respuesta es B, lo bloqueo como Bloque 5 al final (después del polish editorial), no como parte del Bloque 2 de tokens.
